# REQUIREMENTS — Codex 기능 요구사항·데이터 계약·구현 계획·인수 기준

> 프로젝트: 2D 픽셀아트 중세 판타지 모바일 전술 전략 게임  
> 버전: 기획 v12.8 / 2026-11-11  
> 우선순위: **P0** 필수 게임 규칙/저장 무결성, **P1** MVP 콘텐츠/제작 도구/배포 인수, **P2** 후속.  
> 상태: **LOCKED / 확정**, **SEED / 시험 초기값(변경 가능)**, **OPEN / 사용자 미결정**, **DEFERRED / 후속**.  
> Codex에 위임: Godot 리소스/씬/클래스/파일/시그널/API 내부 형태, 재사용 모듈·최적화·테스트 러너 선택. 사용자 승인 없이 게임 규칙과 확정 시스템 계약을 바꾸지 말 것.

## 0. 필수 구현 원칙 및 작업 흐름

- **R-0001 [P0/LOCKED]** 구현 전 4문서를 읽고 `LOCKED`/`SEED`/`OPEN`/`DEFERRED`를 구분해 `OPEN`을 확정값으로 취급하지 않는다.
- **R-0002 [P0/LOCKED]** 시스템 책임과 데이터 경계는 문서대로, 구체 씬/클래스/경로는 Codex 자율 설계. 4문서 밖의 추가 **게임 규칙**은 사용자 승인 없이 확정 금지.
- **R-0003 [P0/LOCKED]** 2D 픽셀아트·세로형·Android 10+·Godot/GDScript·싱글플레이·로컬 저장·수성/공성 MVP. UI는 터치 우선.
- **R-0004 [P0/LOCKED]** 데이터 오류는 `Error`와 `Warning`으로 구분. `Error` 1건 이상이면 빌드 차단 + 콘텐츠 ID/위치/오류 설명 목록. Warning만 있으면 빌드 허용.
- **R-0005 [P0/LOCKED]** 콘텐츠 정의 데이터, 플레이어 영구 진행 데이터, 전투 인스턴스 상태, 에디터 전용 테스트 데이터의 저장/소유 경계를 분리한다.

### 10.2 FPS·Android 인수 [확정 목표 + 구체 계획은 SEED]

- Android 10(API 29) 이상, **보급형 실제 Android 기기 1종 이상** 사용. 모델·OS 패치·GPU/메모리·화면비를 테스트 결과에 기록.
- 일반 전투 **60FPS 목표**, 큰 부하 전투 **30FPS 이상 목표**. 임의의 전역 유닛 하드캡으로 달성했다고 간주하지 않음.
- 성능 기록은 동일 기기·동일 콘텐츠/조건에서 반복 측정. FPS 평균, 프레임 시간(P95 권장), 메모리·AI 평가/경로재탐색 병목, 터치 반응성 기록.
- 수성/공성, 8개 스테이지, 재정비/증원/진화/시설/장애물, 강제 종료·업데이트 시나리오를 실제 기기에서 확인.
- **치명적/진행 차단 오류 0건, 자동 필수 테스트 전체 통과, 콘텐츠 Error 0건**을 초기 인수 기준으로 제안한다. 정확한 측정 길이/합격 프레임 통계는 **[SEED / 추가 실측 설정]**.

### 10.3 CI·배포

- `validate-content → unit-and-integration-tests → export-debug → export-release-test` 순서의 CI 잡 구성을 권장. 정확한 실행 명령은 Codex가 선택·문서화.
- 서명 키·스토어 자격 증명은 리포지터리에 평문 저장 금지. Android 10 실기기 테스트 후 Google Play **비공개 테스트** AAB 빌드까지 준비.
- 광고·과금 라이브러리를 MVP에 넣지 않는다. 콘텐츠는 앱 업데이트에 포함. 업데이트 전 영구 진행 저장 호환성 검증.

## 13. Codex에 전달할 첫 작업 지시(복사 가능)

> 네 개 문서의 `LOCKED`를 사용자 승인 정책으로 취급하고, `SEED`는 조정 가능한 시험 초기값으로 표시하며, `OPEN`은 임의 확정하지 말 것. 우선 M0~M1 수직 슬라이스를 구현하라. Godot/GDScript에서 콘텐츠 정의·런타임 상태·영구 저장·테스트 프로필의 경계를 분리하고, INV-01~13 콘텐츠 검증과 headless CI를 먼저 구축하라. 수성 웨이브·재정비·체크포인트 저장 성공 후 전투 활성화·보상 중복 방지까지 동작하도록 한 뒤 실행 테스트 결과를 보고하라. 확정 규칙을 변경해야 하는 경우에는 코드에서 임의 변경하지 말고 변경 필요성·대안을 별도 항목으로 보고하라.
